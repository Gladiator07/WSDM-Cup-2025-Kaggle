## Solution

### Goal of the competition:

* to predict which responses users will prefer in a head-to-head battle between chatbots powered by large language models (LLMs).
* basically the challenge was to create a “reward” or “preference model” in reinforcement learning from human feedback (RLHF) from the “multi-lingual” conversations registered on Chatbot Arena (previously LMSYS).

### Tried a lot of approaches for finetuning the existing open models for this task:

* Reward models as binary classifier (win/loss probability)
* Bradely-terry loss (ranking)

in the end most of them gave almost similar results but the reward models as binary classifier approach slightly performed better and was more efficient to run.

---

### Core solution:

* The major part of the solution was multi-stage training, large scale pseudo labeling and knowledge distillation.

#### Stage 1:

* took gemma 2 9B as a baseline and pretrained on skywork dataset (`Skywork/Skywork-Reward-Preference-80K-v0.2`) as I found that models pretrained on this dataset performed better on validation and leaderboard in initial stages of the competition.
* also for a mix I added orpo dpo dataset (`mlabonne/orpo-dpo-mix-40k`) from Maxime Labonne.
* I finetuned the model on the combination of these datasets using a simple binary classification head and QLoRA.

#### Stage 2:

* take all the competition data available (past and the current) and train a model on that data (weights initialized from the stage 1 model)

---

### The next step was to generate a good chunk of sythetic data using a diverse set of LLMs.

* I chose around 20 open models based on how recent they are and their popularity on LMSYS.

* I took the `lmsys/lmsys-chat-1m` dataset which only had conversations with a single model.

* I filtered this dataset heavily to only include non-english conversations (as english data as plenty already) and only include single turn conversations giving me around \~126k more samples.

* For each prompt in this dataset, responses were generated from the models using vLLM and huggingface inference API for larger models (>30B range).

* Then I took the stage 2 model and pseudo labeled these synthetic samples.

* I also found that labelling the original training data again with the stage 2 models and using soft labels and training with it improved performance (as the labels in these kind of setups are noisy so we need a soft signal for a model to tune it better).

* I did this for 4 different models: qwen 7B, gemma 9b, gemma 27b and phi 14b.

* And combined their soft labels via weighted ensemble to generate the final labeled dataset.

* Also tta was on while results were being generated.

---

### TTA (test time augmentation)

- First, the model is run with the input formatted as (prompt + response A + response B), and then again with the order swapped as (prompt + response B + response A). The scores from both runs are averaged to get the final prediction. This helps reduce **positional bias**, where LLMs might favor whichever response appears later in the input.

---

### Final training:

I took this final dataset and took gemma 2 9B model and trained and performed knowledge distillation on it with the following losses:

* soft cross entropy loss (for calculating between student model and actual ground truths generated by ensembling)
* kl-divergence loss (for knowledge distillation between different models)
* cosine loss (for aligning the outputs of this models, just another component added)

Here’s the relevant code snippet for this core-part:

```python
class KDTrainer(Trainer):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)

    def compute_loss(self, model, inputs, return_outputs=False, num_items_in_batch=None):
        labels = inputs.pop("labels")  # (bs, num_labels), soft labels
        gemma_9b_logits = inputs.pop("gemma_9b_logits")
        gemma_27b_logits = inputs.pop("gemma_27b_logits")
        phi4_logits = inputs.pop("phi4_logits")

        # get student logits
        outputs = model(**inputs)
        student_logits = outputs.logits

        # regular cross-entropy loss with soft labels
        loss = F.cross_entropy(student_logits, labels, reduction="mean")

        # teacher logits and weights
        teacher_logits = [
            (gemma_9b_logits, 1 / 3),
            (gemma_27b_logits, 1 / 3),
            (phi4_logits, 1 / 3),
        ]

        weighted_kl_loss = 0
        weighted_cos_loss = 0

        for teacher_logits_current, weight in teacher_logits:
            # KL divergence loss
            student_logits_temp = F.log_softmax(student_logits / self.args.temperature, dim=1)
            teacher_logits_temp = F.softmax(teacher_logits_current / self.args.temperature, dim=1)
            loss_kl = F.kl_div(student_logits_temp, teacher_logits_temp, reduction="batchmean") * (self.args.temperature**2)
            weighted_kl_loss += weight * loss_kl

            # Cosine embedding loss
            student_probs = F.softmax(student_logits / self.args.temperature, dim=1)
            teacher_probs = F.softmax(teacher_logits_current / self.args.temperature, dim=1)
            target = torch.ones(student_probs.size(0)).to(student_probs.device)
            loss_cos = F.cosine_embedding_loss(student_probs, teacher_probs, target)
            weighted_cos_loss += weight * loss_cos

        # combine all losses
        total_loss = (self.args.alpha_ce * loss + self.args.alpha_kd * weighted_kl_loss + self.args.alpha_cos * weighted_cos_loss) / (
            self.args.alpha_ce + self.args.alpha_kd + self.args.alpha_cos
        )

        return (total_loss, outputs) if return_outputs else total_loss
```

### Inference:
* For inference I found that 8-bit inference performed faster than 4-bit
* the data was split across two gpus (DDP) that kaggle provides (Tesla T4)
* and test-time augmentation was on in that case.
